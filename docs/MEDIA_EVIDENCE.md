# Media engine evidence

Tested 12 September 2026 on Windows x64 with Node 22.23.2, FFmpeg/ffprobe 9.0.1-full_build-www.gyan.dev and yt-dlp 2026.08.19. Run `npx tsx --test --test-concurrency=1 tests/media.test.ts` to regenerate numbered media, execute real exports, decode results and write a fresh `test-output/media-*/evidence.json`. The completed run at `test-output/media-cCZtkt/evidence.json` passed **19/19** tests. The Linux container run passed **23/23** media/process cases; see `docs/LINUX_EVIDENCE.md`. Generated media is ignored build evidence, not checked-in binary fixtures.

Source coordinates are seconds relative to format start, in-inclusive/out-exclusive. Crop uses encoded/unrotated source pixels; source display orientation is then baked once, followed by recipe rotation, resize, text/captions and encoding. Source cue times intersect each kept segment and map to edited output. Replacement audio starts at output zero; longer audio trims, shorter audio pads silence. Original files are immutable and output paths use no-replace publication.

Known incomplete areas: physical GPU successful encoding/failure recovery; Linux VAAPI device/upload configuration; HDR transforms (explicitly blocked rather than guessed); negative/odd timestamps and exotic containers beyond fixtures; packet-copy audio alignment across wider codec/GOP matrices. Hybrid smart cut is not enabled and remains experimental. Hardware is not cached across jobs, so a persistent driver/device cache fingerprint is unnecessary in this implementation.

Implementation choices were checked against official [FFmpeg options](https://ffmpeg.org/ffmpeg.html), [ffprobe interval/frame documentation](https://ffmpeg.org/ffprobe.html), [filter documentation](https://ffmpeg.org/ffmpeg-filters.html), and [bitstream filter packet timestamp expressions](https://ffmpeg.org/ffmpeg-bitstream-filters.html#noise). The tool documentation is design context; generated output and test assertions are the implementation evidence.
