## Shared containment reviewed

The trusted Windows controller selects an immutable Linux image and administrator-controlled proxy/relay scripts. User JSON cannot choose images, Docker arguments, mounts or executables. Native workers are UID1000/network-none/read-only/cap-drop-ALL/no-new-privileges with PID/CPU/memory bounds. Actual inspection confirms only individually selected read-only host input binds; no Docker socket is mounted.

`/work` is named local-driver tmpfs with byte/inode ceiling and noexec/nosuid/nodev. A named/labeled trusted anchor stages it; native work has no writable host bind. After successful native exit, helpers reject symlinks, hard links, special files, unsafe names and excess entries/bytes, then controller staging is verified before copyback. Canceled work is never copied back. Independent tests inspect writable mounts, force oversized writes and verify cleanup during native/proxy preparation. Additional copyback-link/special-file tests are owned by the worker author.

Download workers have no TCP/DNS route. A read-only Unix socket mount and local relay are their sole channel to a per-invocation filtering proxy. Every HTTP/CONNECT destination is resolved, checked for public addresses and pinned. Actual raw-network/private redirect/nested-HLS challenges pass. Ordinary local proxy filtering is not described as mandatory kernel containment.

Reservations cover **3 × (operation budget + 8 MiB)** for tmpfs, host work and validated staging, shared across each user's jobs/auxiliary requests through cleanup. `/tmp` is an additional private 256-MiB memory filesystem; trusted helpers have separate fixed limits. API transfers share an owner rate; separate downloader proxies have individual budgets with aggregate bounded by concurrency. These are actual bounds, not one global downloader bandwidth counter or zero helper overhead.

The final synthetic shared test exercises this profile through real media and ownership checks. Public reverse-proxy/TLS, Linux-controller/rootless-cgroup behavior, ARM64 and hostile-media sandbox escape resistance are not established. `docs/SHARED_HOSTING.md` correctly requires target-host verification and treats Docker administration as trusted authority.
