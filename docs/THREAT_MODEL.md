# Threat model and tested boundaries

Assets are session credentials, original media, managed artifacts, job integrity, the host filesystem and network. Uploads, URLs and recursive downloader requests, metadata, captions, presets and renderer requests are untrusted. Local executable/tool configuration and the controller's Docker administration are trusted. No telemetry or automatic support-data upload exists.

The authenticated API checks ownership, scopes and current policy. Browser credentials use HttpOnly/SameSite cookies, Secure in shared mode; Host and Origin are validated. General requests and Electron IPC use opaque IDs. The renderer has sandbox/context isolation, no Node integration, no new windows/foreign navigation, and no arbitrary path or executable authority. A separate desktop secret is required to obtain a verified named handoff copy. Editing that copy cannot alter the stored original. Shared mode disables host cookies and native actions even for its owner.

Commands use argument arrays, controlled configuration, bounded output and operation deadlines. Trusted local mode runs tools with the local user's privileges and does not claim an OS security sandbox. Isolated mode injects a server-owned worker runner below the independent media engine; user JSON cannot supply it. The Docker daemon is controller authority and is never mounted into media workers. The tested Linux profile uses UID1000, network none, read-only root, dropped capabilities, no-new-privileges, PID/CPU/memory ceilings, individual read-only source mounts and a bounded tmpfs for job scratch. Implicit image volumes are rejected. Copyback accepts only validated contained regular files and rejects links, special files and unsafe paths. Per-user reservations account for volume, host work and copyback; four host auxiliary operations and two per user bound preview/upload concurrency in addition to the durable job queue.

The downloader's only isolated egress channel is a read-only Unix socket to a dedicated filtering proxy. Every HTTP or CONNECT destination is revalidated and DNS-pinned; private, loopback, link-local, metadata and reserved IPv4/IPv6 addresses are rejected. Raw external sockets and DNS have no worker route. Nested HLS/redirect fixtures and HTTP/TLS first-chunk rate/total-byte limits passed independent tests. The ordinary local proxy also filters and limits traffic, but a proxy argument alone is not an OS sandbox. Per-invocation downloader budgets and the per-user API bandwidth budget are documented in SHARED_HOSTING.md.

Publication follows complete media validation and size measurement. Originals never expire automatically. Retention and explicit deletion use contained paths, dependency checks and deletion guards; active transfers/native handoffs hold renewable leases. History-only deletion retains media; managed-media deletion retains history and never deletes an externally imported source path. Cancellation stops owned processes/containers, and startup cleans only resources labeled for this data directory. Windows attempts a graceful tree close before bounded forced cleanup; Linux sends SIGTERM then SIGKILL. Actual descendant, in-flight download, encode/validation, worker and proxy-preparation cases have been exercised.

Known verification limits remain material: this session did not operate a public TLS endpoint, a native Linux desktop/controller, rootless Docker, ARM64 or a physical GPU. Container/kernel/daemon security is an external dependency, not proved by these application tests. Rerun the named tests on each deployment host. The independent review and implementation ledger distinguish direct reviewer tests, other workers' observed outputs, unavailable platforms, supported fixtures and release-license/signing gates. No public release or upload workflow was authorized or performed.
